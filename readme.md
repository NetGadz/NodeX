# Kademlia DHT

Это экспериментальный проект по реализации распределённой хеш-таблицы на основе протокола **Kademlia**. На текущем этапе проект находится в ранней стадии разработки: базовая логика маршрутизации, хранения и сетевого обмена уже реализована в виде рабочей прототипной системы, но архитектура, API и поведение сети ещё активно меняются.

## Статус проекта

- Стадия: early prototype / pre-alpha
- Цель: изучение и практическая реализация Kademlia DHT
- Ожидания: проект подходит для обучения, экспериментов, доработки и расширения
- Открытость: идеи, улучшения и PR приветствуются

Проект создан как полезная база для дальнейшего развития: можно добавлять новые операции, улучшать маршрутизацию, покрывать тестами, строить более удобный интерфейс и расширять функциональность.

## Что уже реализовано

- ⚙️ **Гибридная архитектура (Rust + C FFI)**:
  - **Rust**: Tokio асинхронный UDP-транспорт, KBucket routing table ($k=20$), параллельный итеративный поиск ($\alpha=3$), метрики, персистентность состояния, REPL.
  - **C FFI**: нулевые динамические аллокации для сериализации/десериализации бинарных UDP-сообщений (`encode_message`, `decode_message`) и криптографический SHA-1 (`hash_node_id`, `c_shared_prefix_bits`).
- 🌐 **Надежный UDP-транспорт**:
  - `request_id` трекинг сообщений.
  - Автоматические повторные попытки (до 2 ретраев) и таймауты (5 секунд).
  - Безопасная обработка сокетных ошибок ОС (включая `WSAECONNRESET` / 10054 на Windows).
- 🗂️ **Kademlia Routing Table**:
  - 160 бакетов по XOR-метрике.
  - Логика вытеснения (eviction policy): пинг наименее активного контакта с заменой при отсутствии ответа.
- 🔍 **Итеративный поиск (Iterative Lookup)**:
  - Параллелизм $\alpha = 3$ для `FIND_NODE` и `FIND_VALUE`.
  - Логирование номеров хопов и миллисекундной задержки.
- 💾 **Хранилище с TTL и Republish**:
  - `STORE` и `FIND_VALUE` с репликацией на $k$ ближайших узлов.
  - Настраиваемый TTL записей и фоновая повторная публикация (republish).
- 🔄 **Safe Restart & Персистентность**:
  - Сохранение `NodeId` и активных контактов в `node_state.json`.
  - Восстановление P2P-идентичности при перезапуске узла.
- 📊 **Метрики и Наблюдаемость**:
  - Отслеживание отправленных/полученных байт и RPC-сообщений.
  - Статистика по средним хопам и времени выполнения lookup.
- 🐳 **Docker & Docker Compose**:
  - Готовый `Dockerfile` (multi-stage) и `docker-compose.yml` для мгновенного развертывания сети из 4 узлов.

## Быстрый старт

### 1. Сборка и прогон тестов
```powershell
# Запуск всех 27+ модульных и интеграционных тестов
cargo test

# Сборка оптимизированного релизного бинарника
cargo build --release
```

### 2. Локальный запуск двух узлов

В первом терминале (Bootstrap-узел):
```powershell
cargo run -- --port 8001
```

Во втором терминале (Второй узел):
```powershell
cargo run -- --port 8002 --bootstrap 127.0.0.1:8001
```

## Работа в CLI REPL

После запуска узла доступно интерактивное приглашение `kademlia> `:

- `put <key> <value>` — записать ключ-значение в DHT (сохранить и реплицировать на $k$ ближайших узлов).
- `get <key>` — выполнить итеративный поиск значения по всей сети.
- `nodes` — вывести список известных контактов в routing table.
- `metrics` — вывести статистику трафика, RPC и поиска.
- `save` — вручную сохранить текущее состояние узла в `node_state.json`.
- `info` — выдать Node ID, адрес сокета и количество хранимых ключей.
- `exit` — сохранить состояние и завершить узел.

Пример:
```text
kademlia> put my_secret "Kademlia P2P Data"
[STORE] Putting key 'my_secret' -> hash 7f8a...
[STORE] Replicated to 2 node(s)

kademlia> get my_secret
=> Found 'my_secret' = '"Kademlia P2P Data"' (from 127.0.0.1:8001)

kademlia> metrics
📊 === Kademlia DHT Node Metrics ===
Traffic:       1240 bytes sent | 1860 bytes received
RPCs Total:    12 sent | 12 received | 0 failed
Lookups:       2 total | 1.50 avg hops | 12.3 ms avg latency
====================================
```
