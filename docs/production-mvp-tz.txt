NodeX Production MVP
Technical Specification

1. Goal
=======

The user must be able to:

1. Download and install the application.
2. Launch it from a desktop shortcut.
3. Create or restore an account.
4. Find another user.
5. Send and receive encrypted messages.
6. Receive messages after being offline.
7. See sent, delivered, and read statuses.
8. Restart the application without losing the account or history.

Manual terminal commands, port configuration, and bootstrap configuration must not be required for normal users.

======================

|  `- serialization.rs

Responsibilities:
- Generate a 12-word mnemonic phrase.
- Validate the mnemonic checksum.
- Derive a deterministic seed.
- Calculate User ID hashes.
- Serialize and deserialize network messages.
- Validate all input sizes and buffers.

If BIP-39 compatibility is claimed, the implementation must use the standard entropy, checksum, PBKDF2-HMAC-SHA512, salt, and iteration rules.

New module requirements:

port_manager.rs
- Select a free UDP port.
- Fallback after WSAEADDRINUSE.
- Report the selected port to the runtime and GUI.
- Never crash the application because the preferred port is busy.

bootstrap.rs
- Store multiple bootstrap addresses.
- Connect automatically on startup.
- Retry with exponential backoff.
- Support standalone mode when no bootstrap node is available.

peer_manager.rs
- Store known peers.
- Track last successful connection.
- Update peer addresses.
- Remove inactive peers after a timeout.

reconnect.rs
- Reconnect after network failure.
- Restore the routing table.
- Republish presence and mailbox metadata.

health.rs

New module requirements:

identity.rs
- Create an account.
- Restore an account.
- Derive User ID.
- Manage Ed25519 signing identity.
- Manage X25519 encryption identity.
- Generate a public-key fingerprint.

mnemonic.rs
- Generate 12 words.
- Validate input.
- Confirm that the user saved the phrase.
- Restore identity from the phrase.
- Never print the phrase to logs.

contacts.rs
- Add and remove contacts.
- Block and unblock contacts.
- Search local contacts.
- Store public keys and fingerprints.

presence.rs
- Publish a signed presence card.
- Set an expiration time.
- Verify the signature.
- Reject changed keys and invalid timestamps.

- Search by User ID.
- Search by username where supported.
- Search through DHT.
- Cache discovered users.

mailbox.rs
Mailbox must be a queue rather than a single mutable value.

Recommended key format:
mailbox/<recipient_id>/<message_id>

Every mailbox message must contain:
- message_id
- sender_id
- recipient_id
- created_at
- expires_at
- status
- encrypted_payload

message_queue.rs
- Maintain outgoing messages.
- Retry failed delivery.
- Deduplicate repeated messages.
- Preserve message order.
- Support offline recipients.

message_status.rs
Required states:
- Composing
- Sending
- Sent
- Delivered
- Read
- Failed
- Expired

Required timestamps:
- sent_at
- delivered_at
- read_at
- failed_at

receipts.rs
- Delivery receipts.
- Read receipts.
- Signed receipts.
- Replay protection.
- Local status updates.

trust.rs
- Show contact fingerprint.
- Confirm a contact key.
- Warn when a key changes.
- Protect against man-in-the-middle attacks.

attachments.rs
- Image and file messages.
- File-size limits.
- MIME validation.
- Encrypted attachments.
- Chunking for large files.

5. Message Lifecycle
====================

Normal flow:

Composing -> Sending -> Sent -> Delivered -> Read

Failure flow:

Sending -> Failed
Sent -> Failed

Each message must contain:
- message_id
- sender_id
- recipient_id
- text or attachment reference
- encrypted payload
- created_at
- sent_at
- delivered_at
- read_at
- status
- retry_count
- last_error

6. Security Requirements
========================

Required:
- Standard BIP-39 mnemonic implementation.
- Ed25519 signatures.
- X25519 key exchange.
- Authenticated encryption for messages.
- Signed presence cards.
- Signed delivery and read receipts.
- Replay protection.
- Fingerprint verification.
- Warning when a contact key changes.
- Secure local storage.
- Windows Credential Manager or password-based encryption.
- No seed phrase in logs.
- Local application lock.
- Secure cleanup of sensitive data where practical.

A hardcoded universal database key is not sufficient production protection.

7. Release Requirements
=======================

- Windows installer or MSI/EXE package.
- Desktop shortcut.
- Application data in %APPDATA%/NodeX.
- No database files beside the executable.
- No terminal required for normal startup.
- Log file available for diagnostics.
- Configuration generated automatically.
- Migration support for database format changes.
- Version information.
- Uninstaller.
- Optional update checker.

8. Definition of Done
=====================

The MVP is complete when:

- The application installs and starts from a shortcut.
- A free UDP port is selected automatically.
- Bootstrap and reconnect happen automatically.
- The user can create and restore an account.
- The user can search for another user.
- Contact keys and fingerprints can be verified.
- Messages work online and offline.
- Repeated delivery does not create duplicates.
- Delivery and read statuses are reliable.
- History survives a restart.
- Errors are displayed in the GUI.
- All workspace tests pass.
- A two-user smoke test passes across different networks.

9. Implementation Priority
==========================

1. Release folders, AppData paths, and runtime configuration.
2. Automatic startup, port selection, bootstrap, and reconnect.
3. Account creation, restoration, and secure local storage.
4. Reliable mailbox queue and message deduplication.
5. User search and contact-key verification.
6. Delivery and read receipts.
7. Notifications and attachments.
8. Installer and update mechanism.
9. Testing across different networks and failure scenarios.
